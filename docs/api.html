音频转写接口

统一接入微信、微信输入法和豆包语音，通过 model 指定后端。

快速接入

Base URLhttp://127.0.0.1:8765/v1

将 OpenAI SDK 的 base_url 指向本机接口地址，再提交音频文件。

POST/v1/audio/transcriptionsmultipart/form-data

默认启动三个独立并发池。实际可用模型以当前服务的 GET /v1/models 返回为准。

模型路由

model调用后端
wechat-voice微信桌面端语音识别
wetype-voice微信输入法语音识别
doubao-voice豆包网页版语音识别

这里的 model 是本地路由标识，不代表上游服务公开的模型名称或版本。model 必填，只接受上述正式名称。每个模型默认并发为 4，各模型独立调度，超出本池并发数时排队。各池并发可在应用设置中调整，不作为转写请求参数传入。

GET/v1/models查询当前服务可用模型

请求参数

参数 / 类型说明
file必填file · 二进制待转写的音频文件，最大 25 MiB。上传文件内容，不接受本地路径字符串或 URL。
model必填string使用上面的路由标识选择后端。服务未提供的标识返回参数错误。
response_formatstring · 默认 jsonjson 返回包含 text 的 JSON；text 返回 UTF-8 纯文本。
streamboolean · 默认 false仅接受 false，当前不提供流式响应。
temperaturenumber · 默认 0仅接受 0。这是兼容参数，不影响上游语音模型。

使用 SDK 或表单库时让库自动生成 multipart boundary，不要手动设置不完整的 Content-Type。

调用示例

Python · OpenAI SDK

from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:8765/v1",
    api_key="local",
)

with open("audio.wav", "rb") as audio:
    result = client.audio.transcriptions.create(
        model="doubao-voice",
        file=audio,
        response_format="json",
    )

print(result.text)

切换 model 即可指定其他后端。启用本地鉴权后，将 local 替换为设置中的 API Key。

Windows PowerShell · curl.exe

curl.exe "http://127.0.0.1:8765/v1/audio/transcriptions" `
  -F "file=@audio.wav" `
  -F "model=doubao-voice" `
  -F "response_format=json"

鉴权

默认仅在本机监听。设置中的「启用 API Key 鉴权」关闭时，任意 API Key、空值或不传 Authorization 都不会影响请求；仅填写 Key 不会启用鉴权。OpenAI SDK 要求提供 api_key，此时可使用任意非空占位值 local。

启用本地 API Key 后，请在请求头传入：

Authorization: Bearer <本地 API Key>

本地 API Key 用于校验调用方，不用于选择识别后端，也不等同于微信或豆包的登录凭据。

响应与错误

JSON 成功响应

{
  "text": "你好，这是语音识别接口测试。"
}

response_format=text 时仅返回识别文字，Content-Type 为 text/plain; charset=utf-8。

错误响应结构

{
  "error": {
    "message": "当前后端不支持流式响应。",
    "type": "invalid_request_error",
    "param": "stream",
    "code": "invalid_request",
    "request_id": "req_..."
  }
}

版本号或模块指纹不匹配只产生警告，不因此拒绝调用。JSON 响应会附带 warnings 数组，每项包含 code 和 message；成功与失败响应均可携带警告。JSON 和纯文本响应同时使用 x-asr-warnings 响应头传递 ASCII 转义的 JSON 数组，纯文本正文仍只包含识别文字。

实际调用失败时，error.message 提供具体原因，error.code 提供错误码，error.details 在有底层异常时提供异常类型、原生错误码或原因链。error.request_id 与响应头 x-request-id 对应。/health 的 last_error_detail 和 warnings 保留各后端诊断；窗口「诊断详情」可以查看并复制。

HTTP 状态含义
400缺少参数、model 不可用，或传入未实现的参数。
401已启用鉴权，但 API Key 缺失或错误。
413上传文件超过大小限制。
500内部调用失败。响应包含具体异常详情。
502 / 503 / 504上游错误、客户端不可用或识别超时；查看响应中的具体原因。

兼容范围

支持音频转写的 json、text 响应，以及 stream=false、temperature=0 两个兼容默认值。

language、prompt、流式结果、逐词时间戳、字幕和说话人分离暂不支持；未实现参数会返回 400。

本页说明本地桥接层的接口约定。可配置并发数不等于上游已验证的稳定并发能力。
